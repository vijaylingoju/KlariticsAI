# ADR-0001: Use the Bearing python-api stack for the service

- Status: Proposed
- Date: 2026-10-11
- Task: KAI-1
- Deciders: Vijay (to accept)

## Context

The brief requires a reusable MCP server, an agent, an API to ask questions and save reports, and offline tests. The owner's team writes Python, and the manager asked for the build to follow Bearing skills only.

## Options considered

### Option A: Bearing python-api scaffold (Python 3.14, FastAPI, Pydantic v2, structlog, uv, ruff, mypy strict, pytest)
Generated by `brg-scaffold python-api`, so Makefile gates, CI, hooks and rules come from Bearing. Its Postgres, SQLAlchemy and Alembic parts do not fit an embedded analytics store and are removed (ADR-0002).

### Option B: TypeScript with the Bearing node stack
The MCP and agent templates exist for TypeScript too, but the team's reference services are Python and analytics code in Python is shorter.

## Decision

We will use the Bearing python-api stack, minus the Postgres layer. Reasons: team language, the strongest Bearing templates for MCP and agents, and the standard gates (`make check`) for free.

## Consequences

- Every gate CI runs is a Makefile target.
- Python 3.14 is new; uv installs it in CI and Docker.
- Revisit if a second service in another language is needed.
